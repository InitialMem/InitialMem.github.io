## Bitwarden中暴露的密码次数的计算方式

首先计算你的密码的哈希值SHA-1，然后只发送前几位，和泄露密码的数据库进行比对，数据库返回匹配该前缀的大量哈希，然后bitwarden在本地计算是否命中，这个数字代表的是密码在已知的泄露数据的数据库中出现的次数，即使次数为1次，也建议更改

## 睡眠和休眠

睡眠和休眠目的都是为了保留工作现场，最主要的区别是工作现场的保存位置不同。

睡眠将程序的状态保存在内存中，需要通电，如果断电可能会丢失未保存的数据

休眠将内存中程序的状态压缩后保存在磁盘中，此后电脑完全断电，断电一般不会丢失数据

如果不需要保留工作现场，那么这两个功能都没有必要。

在有持续电力供应或者电脑不依赖电池的情况下，选择睡眠，功耗减少，不占用磁盘空间，但是可能丢失数据。（台式机，插电运行的游戏本）

如果电量有限，又希望保留现场，选择休眠，其实电脑默认就启用休眠，每次开关机大多数都属于从休眠中唤醒，同时快速启动就依赖休眠。

```bash
REM 查看两者是否开启
powercfg /a
```

## 画素描的反思

画了很多素描，但是没有注意到投影边缘应该锐利，明暗交界线应该稍微模糊。

1. 画之前没有确定目标，需要关注的东西太多，目标模糊，认为画好的状态就是大概像

2. 在画物体，而没有在画关系，很多人想的是眼睛画好没有，这个苹果画的圆不圆，而不是这里的明暗关系是否正确，边缘的软硬是否正确

3. 没有建立检查的意识，每画完一张都要检查：明暗交界线有没有最暗？投影是不是整体偏暗？投影边缘有没有比物体边缘硬？反光有没有超过灰面？高光是不是最亮？

**如何解决**

1. 每次只联系一个知识点：今天只处理二分形状，只练习找明暗交界线，只练反光

2. 画之前提出问题：今天我要验证投影边缘是不是最硬？然后在画的时候问现在这里够硬了吗？

3. 画完检查：大的明暗关系对了吗？明暗交界线画对了吗？

4. 建立错误库：画之前看下之前犯的错误，这次尽量避免

## pnpm的安装

pnpm是nodejs的第三方包管理器，类似npm，和官方的npm的区别如下：

1. 安装包的方式和存储方式不同，pnpm会将第三方包同一放在全局的存储区，不同的项目通过硬/软链接的方式提供，npm会在每个项目的node_modules下都下载一份

2. node_modules更严格，package.json中没有明确引用的包不能直接访问，因为一个依赖可能间接引用了其他依赖，而package.json中没有，但是项目里可以import这个幽灵依赖

**使用corepack安装pnpm**

corepack是包管理器的管理器

首先启动pnpm的命令代理，由corepack处理pnpm命令

```bash
corepack enable
```

然后执行安装命令

```bash
corepack install --global pnpm@latest
```

## 路由器的桥接和Mesh

桥接：指的是将路由器通过网线或者wifi连接起来，将网络延伸出去，让设备处于同一网段，而不是再经过一层NAT/路由

Mesh：指的是Mesh协议，桥接后的路由器可以通过Mesh协议共享网络中设备的连接情况，让路由器提供手机切换网络的建议，而不是仅靠手机自己判断

## CDN

CDN(内容分发网络)，指的是专门用于分发静态资源的网络系统，网站上的一些静态资源可以放在CDN上。
**为什么不放在自己的服务器上？**
如果网站服务器在海外，延迟高，加载会变慢，相比CDN服务提供商会在全球部署多个CDN节点，用户需要资源时会从最近的节点下载
CDN类似缓存服务器，CDN发现自己也没有，会请求你的服务器，然后在本地缓存一份，其他用户访问就可以直接从CDN获取
**浏览器缓存优势**
如果网站A需要vue.js并且已经从CDN获取，那么浏览器会缓存一份，如果网站B也需要，那么可以直接从缓存获取

## CORS

CORS(跨域资源共享)，指的是浏览器的一种安全机制：非同源服务器默认不能共享数据，只有协议，域名，端口相同的地址才算同源
例如：http://localhost:3000请求了http://localhost:8000，由于端口不同，所以他们不同源，浏览器不会把8000返回的数据交给3000
**如果不限制会发生什么**
加入你已经登录了一个银行网站(https://bank.com)，这时你访问了https://evil.com，网站里写了fetch(https://bank.com/api/account)，就可以拿到你银行的信息
**如何解除限制**
后端：浏览器是否允许网站拿到非同源服务器返回的数据靠的是响应头中的CORS头(Access-Control-Allow-Origin : http://localhost:3000)是否符合规则(后端比较请求头中的origin和allow_hosts，返回CORS响应头)
前端：如果修改请求头中的origin呢，请求头中的origin头，由浏览器自动携带，一般不允许修改，但是如果利用postman、curl等工具可以修改，保证数据安全不是CORS的职责，靠的服务端实现的访问控制，CORS只是浏览器添加的一道读取权限检查，如果绕过浏览器，它就没有任何作用
